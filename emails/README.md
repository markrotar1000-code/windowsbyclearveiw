# Estimate notification templates

These source files mirror the raw HTML and plain-text Resend templates used by `functions/api/estimate.js`. Uploading a change leaves a draft; publish the same alias to activate it. They are transactional messages, not marketing campaigns.

| Files / Resend alias | Subject | Reply-to |
| --- | --- | --- |
| `estimate-request.html`, `.txt` / `estimate-request` | `Estimate request — {{{CUSTOMER_NAME}}} in {{{CITY}}}` | Customer email, only when supplied; the API sets this dynamically |
| `estimate-received.html`, `.txt` / `estimate-received` | `We received your estimate request — ClearView` | `owner@windowsbyclearveiw.com` (or configured notification recipient) |

Sender display name: `ClearView Windows & Trim`. Retain the configured, authenticated sender address; the existing default is `estimates@windowsbyclearveiw.com`. The legacy spelling in this email domain is intentional. Website and logo links use `windowsbyclearview.com`.

The request HTML uses escaped `CUSTOMER_NAME_HTML`, `CUSTOMER_PHONE_HTML`, `CUSTOMER_EMAIL_HTML`, `CITY_HTML`, `NOTES_HTML`, and `RECEIVED_AT_HTML`, plus the digits-only `CUSTOMER_PHONE_HREF` and optional `EMAIL_BUTTON_HTML`. The receipt HTML uses escaped `CUSTOMER_NAME_HTML` and `CITY_HTML`. The API must HTML-escape the `*_HTML` values before sending them because Resend triple-brace substitution inserts raw content. Escape ampersands, angle brackets, double quotes and single quotes; preserve note line breaks. `EMAIL_BUTTON_HTML` is the sole intentional HTML fragment: an optional complete table row generated by the API with safely escaped content and a percent-encoded mailto address. It must remain directly inside the action table.

Plain-text alternatives and subjects keep the raw variables without the `_HTML` suffix: request `CUSTOMER_NAME`, `CUSTOMER_PHONE`, `CUSTOMER_PHONE_HREF`, `CUSTOMER_EMAIL`, `CITY`, `NOTES`, and `RECEIVED_AT`; receipt `CUSTOMER_NAME` and `CITY`. This keeps HTML entities out of text and subjects. Register both the raw and escaped variable names in Resend, preserving the triple-brace syntax and API contract.

The current logo is a self-hosted PNG with readable fallback text. Both templates use fluid 600px presentation tables, inline styles, an Outlook width fallback, semantic headings, preheader text and plain-text alternatives. Phone and email links remain usable without loading images. The customer receipt contains no internal links, project notes, tracking history, measurements or pricing. It does not promise a response deadline or imply an appointment was already booked.

Render synthetic examples at phone and desktop widths before publishing; include long names, long addresses, multiline notes, HTML-sensitive characters and a missing customer email. Browser previews do not replace physical Outlook/Gmail/Apple Mail testing. Do not send tests to real customers.
